## Before you go live

1. **Secrets** — generate a real `SESSION_SECRET` and `ENCRYPTION_KEY`
   (`node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`).
   The config layer refuses to boot in production with the placeholders.
2. **Cookies / CORS** — `COOKIE_SECURE=true`, set `COOKIE_DOMAIN`, and list only
   your real origins in `CORS_ORIGINS`.
3. **Storage** — switch `STORAGE_DRIVER=s3` for multi-host deployments. The local
   driver is anchored to the workspace root so the API and worker share a folder,
   which only holds when they run on the same machine.
4. **Index verification** — set `SERP_API_ENDPOINT` and `SERP_API_KEY` from your
   licensed SERP data provider. Without them the checker reports an error rather
   than inventing a verdict, so no customer ever sees a fabricated "indexed".
5. **Payments** — set `PAYMENT_DRIVER=stripe`, `STRIPE_SECRET_KEY` and
   `STRIPE_WEBHOOK_SECRET`, and point the Stripe webhook at
   `POST /api/v1/webhooks/payments`.
6. **Email** — `EMAIL_DRIVER=smtp` with real relay credentials.
7. **Discovery providers** — enable what you have contracts for in the admin
   panel. `mock` is development only; disable it in production.
8. **Migrations** — deploy with `pnpm db:migrate:deploy`, never `migrate dev`.
9. **Processes** — run `apps/api`, `apps/worker` and `apps/web` as three
   services; scale the worker independently.
